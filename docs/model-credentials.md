# 模型凭证与重启

模型供应商的 API Key 以 AES-256-GCM 密文保存。保存凭证前必须为服务配置稳定的加密密钥：优先使用 `SECRET_KEY`，未设置时使用 `AUTH_SECRET`。建议生产部署使用独立的 `SECRET_KEY`，通过部署环境注入，并在重启后保持相同值。

## 首次配置

1. 在运行服务的环境中设置足够随机的 `SECRET_KEY`，不要把真实值提交到仓库、放进截图或发送给其他人。
2. 重启服务使环境配置生效，再到模型管理保存供应商 API Key。
3. 检查模型连接，重启后再检查一次，确认数据库和加密密钥均持久保存。

未配置稳定密钥时，模型管理拒绝保存或替换非空 API Key，返回明确的 `503` 错误，不再生成只能在本进程使用的临时加密密钥。无凭证的供应商配置仍可保存；已有的环境模型配置仍可直接使用，启动不会因为缺少加密密钥失败。

`GET /api/models` 的 `encryption` 字段只返回 `configured` 与可选的 `problem`，不返回加密密钥或指纹。

IM 机器人凭证共用这套加密配置。缺少稳定密钥时，新增或替换机器人凭证同样返回 `503`；已有机器人列表仍可打开，发送和回调使用凭证时明确报告配置问题。

## 旧凭证无法解密

如果旧版本曾在未配置稳定密钥时保存 API Key，服务重启后原进程密钥已经丢失，无法从数据库恢复明文。先固定加密配置，再到模型管理重新填写供应商 API Key。不要把数据库中的密文当作 API Key 粘贴回去。

若是在更换 `SECRET_KEY` 后才出现问题，优先恢复原密钥；更换密钥前需要设计并执行凭证重新加密流程，不能只修改环境变量。

## 备份与验证边界

数据库备份不包含部署环境中的加密密钥。恢复时必须同时恢复对应密钥；应分别安全保管，限制访问权限。使用 `AUTH_SECRET` 作为加密密钥时，轮换登录签名密钥也会影响凭证解密。

`npm run models:selftest` 使用测试密钥与临时数据库，覆盖独立进程解密、模型选择恢复、缺配置时拒绝写入且无部分更新，以及环境模型仍可启动。该测试不会调用真实模型供应商，供应商凭证是否有效仍需实际连接验证。
